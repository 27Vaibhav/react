🔄 React App Flow: Conceptual Overview-:

1)At a high level, both CRA and Vite do the same thing:
2)HTML entry point (e.g., index.html)
3)JavaScript entry point (e.g., index.js or main.jsx)
4)React DOM renders the app into a <div> inside the HTML
5)React Components build the UI in memory (virtual DOM) and update the real DOM efficiently
----------------------------------------------------------------------------------------------------------

🔹 1. The HTML File – public/index.html
In a typical React app (like one created with create-react-app), there's a file

This is the base HTML file. It usually looks like this:

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>React App</title>
  </head>
  <body>
    <div id="root"></div>
  </body>
</html>

🔸 Key Detail:
->The <div id="root"></div> is where React will "inject" your application.
->It's the only HTML you manually write — React takes over from here.
->But here we haven't call any js means we are not loading so here if you go to package.json you will see in scripts that there react.script something that works in background and load it in html.This is for app craeted using create-react-app.

----------------------------------------------------------------------------------------------------------

🔹 2. JavaScript Entry Point – src/index.js or src/main.jsx
This file is the entry point of the React app. It renders your entire app into the #root element in the HTML file.

Example: src/index.js

import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';

const root = ReactDOM.createRoot(document.getElementById('root'));
root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);

🔸 Key Detail:
->ReactDOM.createRoot(...).render(...) is the function that injects the React component tree into the HTML.
-> <App /> is your top-level component.
->Creates a virtual dom(ReactDOM) and then compare it with og dom  and then change only that part of og dom which is different.


**Imports the React library**, which is required for writing components using JSX (e.g., `<App />`).
Even though you don't always call `React` directly, JSX needs it to compile behind the scenes.


->document.getElementById('root') selects the <div id="root"></div> in your public/index.html.
->ReactDOM.createRoot(...) sets up the new React root rendering context.
->This tells React: "Mount the entire app into this DOM node."


root.render( <React.StrictMode> <App /> </React.StrictMode> );
- This **renders** your `<App />` component **inside the `#root` div**.
- `<React.StrictMode>` is a helper component used only in development to highlight potential issues:
  - Warns about deprecated APIs
  - Checks for side-effects
  - Helps with best practices
- It **does not render anything visible** and has no effect in production.


### 📦 What happens under the hood?

- React converts `<App />` and its children into a **virtual DOM**.
- Then it **efficiently injects** that into the real DOM element (`<div id="root">`).
- Your React app is now “alive” on the page and reactive to state/prop changes.

🔹 3. Your Component Tree – src/App.js and others
Now React takes over. It builds a virtual DOM and updates the real DOM efficiently. Your app usually starts here:

// App.js
import React from 'react';

function App() {
  return (
    <div>
      <h1>Hello React</h1>
    </div>
  );
}

export default App;

->You can nest more components inside App to create complex UIs.
->The function/Component name should have starting letter capital function App so here A is capital its compalsory/mandatory.
->Try to name files in first letter capital its good practice.
->If vite then .jsx always if create-react-app then js or jsx any.

🔹 5. React Virtual DOM & Rendering
React builds a Virtual DOM — a lightweight JS representation of the real DOM.

When state or props change, React:
->Creates a new Virtual DOM.
->Diffs it with the old one.
->Applies only the necessary changes to the real DOM efficiently.

This is why React is fast and reactive.
